# Easel Studio 0.0.2

## Codex and media

- Enable Codex's tool host and connect Easel MCP before starting a turn, including restored conversations.
- Use native Codex image generation alongside configured Easel image and video models. Requests for a named endpoint use its model ID from `list_models`.
- Keep an already loaded Codex thread between turns and return a structured media model list.
- Restore saved live screenshot previews in chat and preview canvas recordings when captured.
- Show when media is already saved and the agent is preparing its follow-up reply.
- Keep accepted media jobs downloading after Stop without automatically restarting the stopped agent turn.
- Keep media labels visible and clickable in assistant replies; avoid empty lists after preview captions are assigned.
- Remove the 32 MiB total project media cap and check available disk space before saving images, recordings, and project data.
- Return media references newest first with timestamps, and guide native image lookup to the shared library.
- Share concise harness instructions across agent backends, reuse known model IDs, and remove duplicate provider polling guidance from queued job receipts.
- Acknowledge generated media with its automatic inline preview instead of ending replies with a View or Watch link.
- Let video endpoints choose their default size when dimensions are omitted; reference-image dimensions do not determine video dimensions.

## Workspace

- Use the outline SVG easel mark in the app header, desktop windows, installers, and Windows, macOS, and Linux packages.
- Use one viewer tab row, with a trailing **+** for new HTML canvases and a status dot beside each document title.
- Open the Files drawer by clicking the selected document tab. Project ZIP download, Undo, and document device settings live in the drawer.
- Replace chat and media action labels with accessible icons and consistent spacing.
- Sort project media and the shared library newest first using media timestamps.
- Choose available kits while creating a project; new HTML canvases inherit its kit selection.

## Canvas tools

- Return compact source contracts and omit media manifests from file listings by default; full diagnostics remain available through `inspect_canvas`.
- Return saved source paths and revisions from `present_canvas` so agents can edit extracted scripts and styles directly.
- Guide agents toward bounded source reads, atomic edit batches, and one reload and capture with validation.
- Guide p5 sketches toward bounded mount sizing so responsive canvases do not overflow or grow their own containers.
- Report enabled kits in canvas-creation receipts and return targeted corrections for duplicate document paths and blocked CDN dependencies.
- Validate source references in every HTML document before committing edits, including atomic patch batches; missing kits direct the agent to user enablement.

Windows installers and ZIPs, signed and notarized macOS packages, and Linux AppImage and Debian packages are attached by the tag build workflow.
